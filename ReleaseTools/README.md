# Инструмент подготовки релизного проекта приложения

Этот каталог содержит выпускной инструмент для приложений BroadApps. Он переносит используемые внутренние Swift-пакеты в релизную копию, создаёт отдельную ветку `release/<версия>` только с подготовленными файлами и отправляет её в GitHub. Сторонние зависимости остаются удалёнными. После разовой настройки приложения разработчик запускает одну команду: `bash Scripts/prepare_release.sh`, затем вручную выбирает эту ветку в Codemagic.

## Подключение к приложению

Из корня integration repository один раз выполните:

```bash
bash ReleaseTools/install.sh /path/to/MyApp MyApp.xcodeproj MyApp
```

Installer добавит четыре файла в `Scripts/` приложения и исключит `ReleaseExport/`, `ReleaseBranches/` и `ReleaseRecords/` из основной ветки Git. Он не перезаписывает существующий инструмент. Владелец приложения один раз создаёт `Scripts/codemagic.release.yaml`: конфигурация должна собирать проект из корня релизной ветки, запускать `Scripts/check_release_source.rb` до сборки и `Scripts/check_release_artifact.rb` перед публикацией IPA. Настройте в ней signing и publishing конкретного приложения. В 5112 есть пример такой конфигурации. Проверьте diff и сохраните файлы в репозитории приложения.

После коммита изменений разработчик запускает `prepare_release.sh`. Команда проверяет сборку без подписи, создаёт из чистого экспорта новую ветку `release/<версия>` без истории основной ветки, проверяет её файлы и отправляет в GitHub. Код и `codemagic.yaml` для этой ветки берутся из релизного экспорта и шаблона приложения; исходные ссылки на наши Git-репозитории в ветку не попадают. В Codemagic разработчик вручную выбирает ветку и запускает workflow. CI устанавливает сторонние зависимости, собирает IPA, проверяет исходники и артефакт, затем публикует в App Store Connect.

Подробный отчёт `ReleaseRecords/<версия>.json` остаётся локально вне релизной ветки. CI создаёт свой короткий отчёт в `ReleaseRecords/` как отдельный artifact, не включая его в IPA. Скрипт проверки `.ipa` отклоняет служебный отчёт и ссылки на Git BroadApps внутри приложения. Без подписанного архива можно проверить исходники и компиляцию; релизный CI отдельно проверяет готовый `.ipa`.
