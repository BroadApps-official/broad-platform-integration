# Инструмент подготовки релизного проекта приложения

Этот каталог содержит исходную версию выпускного инструмента для приложений BroadApps. Он переносит только используемые внутренние Swift-пакеты в релизную копию проекта и оставляет сторонние зависимости удалёнными. После установки разработчик приложения запускает одну команду: `bash Scripts/prepare_release.sh`.

## Подключение к приложению

Из корня integration repository один раз выполните:

```bash
bash ReleaseTools/install.sh /path/to/MyApp MyApp.xcodeproj MyApp
```

Installer добавит три файла в `Scripts/` приложения и исключит `ReleaseExport/` и `ReleaseRecords/` из Git. Он не перезаписывает существующий инструмент. Проверьте diff, затем сохраните файлы в репозитории приложения. Для обновления инструмента сравните изменённые файлы с этим каталогом и перенесите обновление отдельным PR.

В app CI порядок таков: `prepare_release.sh --skip-build` → установка сторонних зависимостей в `ReleaseExport/<версия>` → сборка из него → `prepare_release.sh --audit` → проверка готового `.ipa` через `check_release_artifact.rb` до загрузки в App Store Connect. В 5112 есть рабочий пример маршрута Codemagic.

Отчёт `ReleaseRecords/<версия>.json` хранится с внутренними CI artifacts, вне `ReleaseExport/`. Скрипт проверки `.ipa` отклоняет служебный отчёт и ссылки на Git BroadApps в приложении. Без подписанного архива можно проверить исходники и компиляцию; релизный CI отдельно проверяет готовый `.ipa`.

[Короткая инструкция для разработчика на сайте](https://broadapps-ios-docs.nkhsnv.chatgpt.site/docs/app-release-export).
