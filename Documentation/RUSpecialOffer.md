# RU Billing: Special Offer — RU-продукт

Эта страница описывает только одно: **откуда берётся продукт** для экрана
Special Offer в RU Billing. Сам экран, флаг показа и цикл «окно оффера →
cooldown» работают так же, как в общей статье
[«Спешл оффер (от Adapty)»](SpecialOffer.md); RU-часть меняет лишь источник
продукта.

Базовые вещи должны быть уже подключены: обычный RU Billing по статье
[«RU Billing»](RUBilling.md) и обычный Special Offer от Adapty.

## Откуда берётся RU-продукт

Продукт для экрана Special Offer в RU берётся из **платёжного каталога
backend**, не из Adapty и не из App Store.

- в каталоге он помечен отметкой Special Offer — строгим булевым полем
  `isSpecialOffer` (согласованный wire alias `is_special_offer` также
  декодируется); приложение выбирает его только по этой отметке, не по цене,
  названию, периоду или позиции;
- `productId`, цену, валюту, display price и период экран берёт из этой строки
  как есть;
- отметку проставляет тот, кто ведёт RU-админку, по согласованному id продукта;
- обычный paywall эту строку исключает — она только для Special Offer;
- если строки с отметкой нет, обычный тариф не подставляется — экран остаётся
  без продукта;
- порядок backend-каталога и дубли сохраняются; скрытая сортировка,
  дедупликация и fallback запрещены.

## Что передать в RU checkout

RU checkout принимает точный выбранный продукт из каталога backend:

```text
Код продукта: <productId из помеченной строки каталога>
Цена:          <цена и валюта из той же строки>
Статус:        активен
```

`productId` передаётся без подмены. Не копируйте app-level переключатель
«сделать все продукты разовыми»: тип оплаты задаёт базовая настройка RU Billing
приложения.

## Шаги в приложении

1. Запросите каталог с backend тем же авторизованным клиентом, что в основной
   статье RU Billing.
2. Выберите продукт со строгой отметкой Special Offer.
3. Передайте именно этот объект и его `productId` в уже реализованный RU
   checkout.
4. Premium открывайте только после подтверждения оплаты на backend — возврат из
   браузера оплатой не считается.
5. Подтверждённая покупка или restore сбрасывают общий цикл Special Offer.

## A/B-тесты

A/B-тесты RU Billing сейчас **не поддержаны и находятся в разработке**.
Инструкций по их настройке нет. Adapty может назначать варианты своего paywall,
но приложение не создаёт второй client-side randomizer и не переносит это
назначение на RU-продукт самовольно.

## Как проверить

- отмеченная строка не появляется в обычном RU paywall;
- Special Offer использует только отмеченную строку и её точные коммерческие
  данные;
- отсутствие отмеченной строки не подставляет обычный тариф;
- неподтверждённый возврат из браузера не открывает Premium;
- активный entitlement блокирует offer до загрузки продукта.
