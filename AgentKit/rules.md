# Правила разработки iOS-приложений BroadApps

Файл ставится в глобальные правила агента (Claude — `~/.claude/CLAUDE.md`, Codex —
`~/.codex/AGENTS.md`) командой `bash AgentKit/install.sh`. Источник правды —
платформа: сайт https://broadapps-ios-docs.nkhsnv.chatgpt.site/ и репозиторий
`BroadApps-official/broad-platform-integration`. Правило платформы важнее частной
реализации отдельного приложения. Если задача глубоко касается монетизации,
onboarding или RU Billing, перечитай документацию платформы: она может быть новее.

Приоритет: прямое указание пользователя в чате → `CLAUDE.md`/`AGENTS.md` репозитория →
этот файл.

## Общее

- Отвечай по-русски и простыми словами.
- Не заявляй PASS или «работает», если последняя сборка или проверка упала. Не отключай
  и не ослабляй проверки ради зелёного результата — ищи первопричину.
- Неизвестный экран, endpoint, backend hook, product ID или правило не придумывай:
  помечай `BLOCKED` и задай один прямой вопрос. Fixture не выдавай за production flow.
- Не добавляй в код и логи secrets, реальные ID, credentials и raw
  error/URL/receipt/JWS/token/user/payment data.
- Комментарии в коде — только на английском. Тексты интерфейса — на языке продукта.
- В коммиты не добавляй трейлер `Co-Authored-By` и строки об авторстве ассистента.

## Как идёт работа над приложением

- Только по этапам с остановками: preflight → план `Documentation/AppIntegrationPlan.md`
  без Swift → каркас → по одному разделу → поведение → внешний вид → передача. Каждый
  этап заканчивается фразой «НУЖНА ПРОВЕРКА …» и одной строкой «что проверить».
- Backend уже работает в референсе? Следуй `Documentation/AgentPreflight.md` и
  `Documentation/AppCreationWorkflow.md`: читай референс без правок, сохрани
  commit SHA, создай `Documentation/BackendContract.md` на этапе плана и
  согласуй расхождения с владельцем backend. Переноси подтверждённое поведение
  через адаптеры платформы, без старой архитектуры и хардкода; контент и
  продукты бери с backend/Adapty. Чужие production URL, секреты, email,
  checkout URL, SKU и персональные данные автоматически не копируй. Адрес нового приложения
  подтверждается отдельно; неизвестное — `BLOCKED` и конкретный вопрос.
  `TEMPORARY` относится только к выбранным разработчиком данным Adapty,
  Debug-продуктов и legal с источником и условием замены, не к серверным
  секретам и production URL.
- В начале разговора про любое приложение проверь и скажи: есть ли алерт обновления
  на главном табе и заведены ли все плейсменты Adapty.
- Аккаунта ещё нет (метка «Жду аккаунт»: нет ключа Adapty, продуктов, PP/ToU)? Спроси
  разработчика, данные какого похожего приложения компании взять (с токенами, если они
  нужны) — сам не выбирай. Временно возьми его ключ Adapty, плейсменты, продукты
  (`.storekit`) и ссылки в одном месте конфигурации с пометкой
  `TEMPORARY: <номер приложения>`. Перед выпуском замени на данные приложения.
- Пока данные `TEMPORARY`, показывай реальные цену, название и количество товаров
  похожего приложения из Adapty/StoreKit и backend. Числа и названия тарифов в Figma
  (например, «1000 / 100 images / $80») — только пример дизайнера; не переноси их
  в код или на экран.
- Покупки в Debug идут через локальный `.storekit` схемы — он применяется только при
  запуске из Xcode (Run). Для проверки пейвола и покупок запускай приложение сам:
  `osascript -e 'tell application "Xcode"' -e 'set ws to active workspace document' -e 'set active run destination of ws to (first run destination of ws whose name is "<simulator>")' -e 'run ws' -e 'end tell'`.
  Не проси разработчика запустить его. `simctl install/launch` не подключает
  `.storekit`: тарифов нет, купить нельзя. Если разработчик уже запустил
  приложение из Xcode, не нажимай в его сессии. Сборка без подписи ломает
  Keychain. Покупки за реальные деньги, restore и RU-оплату не выполняй.
- В `.storekit` заведены все продаваемые приложением продукты плейсментов Adapty с
  ценами App Store: подписки основных пейволов, продукт `special_offer` и
  consumable-пакеты токенов, включая placement `tokens`. Файл добавлен в проект
  (иначе в схеме он красный) и не копируется в приложение. Пейвол показал меньше
  товаров, чем в Adapty, или в логе DEBUG есть `missing vendor product IDs` —
  сначала допиши продукты в `.storekit`. Проверка:
  `ruby <skills>/broadapps-new-app/scripts/check_debug_storekit.rb . --expect <ID>`.
- Название тарифа формирует приложение, а не App Store: аккаунт-менеджер пишет в имя
  продукта его ID, и в проде `displayName`/`localizedTitle` — это ID. Имя из StoreKit
  (`plan.title`, `package.title`) не показывай. Подписка — по периоду из данных
  продукта («Yearly», «Monthly», «Weekly»); пакет токенов — «N Tokens», где N из
  каталога backend (credits по product ID), а без него — ведущее число из product ID
  (`50_Tokens_9.99` → 50) только для надписи, не для зачисления и баланса. На
  платформе — готовые `plan.name` и `package.name` (UIFlows 7.0.0+; со своими
  текстами включи их параметрами `planNames`/`tokenName`).
  `displayName` в Debug `.storekit` заполни как в App Store, без цены.
- Каждый путь покупки в Debug использует `LocalStoreKitPurchaseRepository`:
  подписки основных пейволов и спецоффера через `PurchaseSelectedProductUseCase`,
  пакеты токенов через `TokenPurchaseManager`. В Release покупка идёт через Adapty.
  Проверь оба подключения: локальный StoreKit только у подписок или отсутствие
  токен-пейвола оставляют путь покупки непроверенным.
- Срез с покупками готов только после того, как ты сам запустил Debug из Xcode и
  купил каждый тип продукта: появился лист оплаты, покупка прошла, доступ или
  подтверждённый баланс обновился. Если backend отклонил транзакцию из `.storekit`
  (например, HTTP 422), сообщи разработчику код ответа и что нужно от backend;
  локально зачисление не имитируй.

## Figma

- Figma открывай в браузере, где разработчик вошёл в аккаунт (computer use / браузер
  агента). MCP Figma не нужен.
- Шрифт, размер, вес, межстрочный интервал, трекинг, цвета, отступы, радиусы и
  auto-layout читай на панели свойств справа: выбери слой (Cmd+клик — вложенный,
  Shift+Enter — родитель). Стили текста и цветов файла видны без выделения.
- Фоны и картинки выгружай сам: слой или кадр → Export → `6x` PNG → в ассеты
  (`@3x`, фото — JPEG). Базовая ширина вёрстки — ширина кадра Figma.
- Кадр «rate us» рядом с онбордингом — отдельный экран после успешной генерации, не
  слайд онбординга.

## Устройства: iPhone, но проверка на iPad

- Только iPhone: `TARGETED_DEVICE_FAMILY = 1`, без iPad/Mac/Catalyst/visionOS targets.
- Apple проверяет приложение и на iPad: там оно открывается в окне режима
  совместимости. Кнопки окна стоят слева сверху, окно бывает выше любого iPhone. Каждый
  экран проверь на iPad-симуляторе и iPhone SE: текст виден и не обрезан, крестик,
  Restore, Terms и Privacy не перекрыты и нажимаются, арт не оставляет пустых полос.

## Архитектура и вёрстка

- Clean Architecture + MVVM + SOLID, зависимости внутрь. View не получает зависимости
  через resolver и не создаёт use case/repository.
- Экран = только вёрстка: свои онбординг, пейвол, токены и настройки рисуй внутри
  `BroadOnboardingFlowHost`, `BroadPaywallHost`, `BroadTokenPaywallHost`,
  `BroadSettingsHost` из готового `screen`; не копируй покупку, restore, крестик, таймер
  оффера и защиту от двойного нажатия. Главный таб — с `.broadAppUpdateAlert(checker)`.
- Размеры через `.scale` от ширины кадра Figma (коэффициент 0.85…1.25); spacing,
  радиусы, размеры — токены дизайн-системы, литералов во `.frame`/`.padding` нет.
- Шрифты не масштабируются от экрана: text styles или кастомный шрифт с Dynamic Type.
- Hit area кнопок, продуктов, restore, legal и close — не меньше 44×44 pt.

## Onboarding, ATT, Rate Us

- ATT — только после появления первого слайда, никогда в loader. С BroadUIFlows 7.1.0
  задержка считается от конца перехода к слайду; на 7.0.0 и раньше — не меньше
  длительности перехода + 400 мс.
- Rate Us и review API запрещены внутри onboarding.
- Количество слайдов задаёт только `OnboardingConfiguration.pages`; неясно — спроси.

## Плейсменты Adapty

| Где пейвол | Placement ID |
|---|---|
| После онбординга | `onboarding` |
| Кнопка Premium/Pro | `pro_icon` |
| Настройки | `settings` |
| Основной и резервный | `main` |
| CTR-кампания | `CTR` |
| Спешл оффер | `special_offer` |
| Покупка токенов | `tokens` |

ID совпадают с Adapty символ в символ. `tokens` и `special_offer` без fallback на `main`.

## Пейвол и продукты

- Токены — только если они есть в приложении (`tokens.mode = backend` в
  `Configuration/AccountIntegration.json`); без токенов — `notUsed` с причиной, без
  токен-пейвола и плейсмента `tokens`. Решаешь на preflight по Kaiten, Figma и backend;
  нет ответа в источниках — спроси.
- Если токенов не хватает для генерации, повтора, шаблона или «ещё раз», сразу
  открывай пейвол, без алерта «пополните позже». Тап по балансу ведёт туда же:
  без подписки — подписочный пейвол кнопки/экрана (обычно `pro_icon`), с подпиской
  — токен-пейвол `tokens` через `BroadTokenPaywallHost`. После покупки перечитай
  подтверждённый `TokenBalanceSnapshot` с сервера; действие пользователь
  запускает сам, без автоповтора. Если backend требует подписку для токенов
  (`403 subscription_required`), отправляй её на backend после покупки, Restore
  и при запуске (`subscription/sync` или аналог), иначе кредиты и покупка токенов
  не заработают.
- Продукты только из Adapty (`getPaywall → getPaywallProducts → 1:1`), без хардкода цен,
  периодов и фикстур. Trial в приложениях BroadApps нет.
- Подписки от длинного периода к короткому, при открытии выбрана самая длинная — это
  делает платформа, экран не сортирует.
- Строка тарифа или пакета токенов — не `Button`: `.contentShape` + `.onTapGesture`,
  без затемнения и press-эффекта. Во время покупки — лёгкий блюр и спиннер.
- Крестик пейвола — через 5 секунд (или `closeDelay` из Remote Config).
- Цена в строке тарифа: крупно и справа — сумма, которая реально спишется, с периодом
  (`$59.99 / year`); недельный эквивалент — только мелко под названием тарифа. Иначе
  Apple отклоняет сборку, даже если в Figma наоборот.
- Special Offer — вторым пейволом после закрытия любого обычного пейвола без покупки
  (после онбординга, с кнопки PRO, из настроек); строгий bool `special_offer = true`;
  в окне 24 ч он показывается после каждого закрытия, затем cooldown 24 ч. Появляется
  сразу по крестику: пока обычный пейвол открыт, вызывай
  `ResolveSpecialOfferUseCase.prepare(configuration:)`. Оффер продаёт один продукт:
  одна карточка без выбора, даже если в макете две строки. Зачёркнутая цена и процент
  скидки считаются из цен: тариф того же периода и валюты с закрытого пейвола.
- Экран выезжает целиком: начинай анимацию, когда его данные уже на экране. Вью,
  которые появились во время движения, встают сразу на место и «выпрыгивают» раньше
  экрана. Пейвол с кнопки PRO или из настроек загружай заранее
  (`BroadPaywallPreloader`), чтобы шторка выезжала сразу с тарифами. Токен-пейвол
  (если в приложении есть токены) — так же: `preload(.tokens)`, пока виден экран с
  балансом, и `initialPayload: preloader.take(.tokens)` в
  `BroadTokenPaywallViewModel` — экран открывается сразу с пакетами (UIFlows 7.0.0+).
- Purchase/restore не открывают premium до подтверждения доступа. Offline/timeout не
  превращаются в success/inactive.

## Settings, обновление, поддержка

- Settings: одно касание за раз (общий gate ~400 мс) — это делает `BroadSettingsHost`.
- Подписка через Adapty/App Store: «Cancel subscription», системный экран и
  веб-страница подписок App Store не показываются, даже если нарисованы в Figma.
  «Get Pro», статус подписки и «Manage subscription» открывают пейвол
  (`BroadSettingsHost(configuration:showPaywall:…)` — BroadUIFlows 7.0.0+, обязательный
  `showPaywall`, через общий tap gate). На 6.x `manageSubscription()` ведёт в App Store —
  обнови UIFlows. Отмена — только в RU Billing через backend.
- Алерт обновления на главном табе: версия App Store по bundle id, базовая версия в
  `UserDefaults`, числовое сравнение, без сети — без алерта (`.broadAppUpdateAlert`).
- Письмо в поддержку — строго по шаблону `SupportEmail.md` платформы, без строки `Bundle`.
  Без системной почты окно «Скопировать адрес» / «Закрыть» показывает `BroadSettingsHost`
  (BroadUIFlows 7.1.0+); своё не дублируй.
- Нет App Store ID — `BroadSettingsConfiguration.withAppStoreLink(userID:appStoreLink: nil, …)` (7.1.0+):
  «Поделиться» и «Оценить» скрыты; чужую ссылку или выдуманный ID не подставляй.

## RU Billing (если подключён)

Регион: Storefront `RU/RUS` или регион iPhone `RU/RUS`. `ru_pay` отсутствует/false —
закрыто, `true` не подставлять. Каталог backend 1:1. Подробности — `RUBilling.md`.
«Настройки → Информация о компании» (реквизиты 1payments) — только если подключён RU
Billing; реквизиты из документа Kaiten перед добавлением и перед выпуском подтверждай у
аккаунт-менеджера на актуальность, не копируй из другого приложения или скриншота.

## Ограничения среды

- У разработчиков нет TestFlight и нет доступа к кабинетам Adapty и App Store Connect:
  все доступы — у аккаунт-менеджеров. Настоящую покупку проверить нельзя и требовать
  этого не нужно. Покупки проверяются в Debug запуском из Xcode с локальным `.storekit`
  (тестовый лист, деньги не списываются) и сборкой Release без подписи.
- Плейсменты, продукты, Remote Config (`special_offer`, `closeDelay`, `ru_pay`) меняет
  аккаунт-менеджер: не открывай кабинеты, а напиши разработчику, что попросить у него.
- `Team = None`, iPhone Simulator и generic `iphoneos` без подписи; archive и `.ipa` не
  собирать. StoreKit sandbox недоступен — не требовать.
- Платёжный кабинет и кабинет Adapty не открывать и не менять.
